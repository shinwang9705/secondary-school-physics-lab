# 技术调研与适用性（优化版）

原调研报告作为历史资料保留，不把其中“来源待 R3”“多校私有云”“本地兜底模型”等旧建议直接带入实现。自研指自行控制实验模型、器材交互及判据，不禁止使用通用开源工具。

此前电路台具备节点/电源支路方程求解，凸透镜作品具备薄透镜近似与 SVG 光路；本轮复用这两个已存在的交互作品，并将电路求解器提取成服务端可复算的纯模块。

Three.js 是 3D 图形库，Rapier 提供实时物理中的力、碰撞与约束等能力，均不能替代电路、光学、热学等模型规格。第一版电学与光学使用 SVG，后续必要时接入 Three.js/Rapier；不将 3D 视为实验质量验收条件。

参考：[Three.js 官方说明](https://threejs.org/manual/pages/fundamentals.html)、[Rapier 官方说明](https://rapier.rs/docs/)。上述能力边界在前次评估已核对，本轮不以此声称验证任何新引擎版本。

第一版使用本机已有 Node.js 24.11.1 与内置 SQLite，减少安装和运行组件。node:sqlite 在该运行时仍会输出实验性功能警告，应锁定 Node 主版本；未来升级时先跑数据库与权限测试。当前实现不依赖原调研报告锁定的老版本 Java/Python/Three.js 组合。

AI 解释与判定解耦；未配置第三方 API 时依然能完整执行首批实验。v1.0 实现可选通用教学解释网关，本地模拟服务已验证；实际供应商、模型、费用与数据处理范围需部署时确认。

v0.2 力学采用自行实现的确定性公式与 SVG：弹簧、杠杆、静态浮力、匀速/匀加速直线运动。当前参数范围可用解析模型表达，未引入通用碰撞引擎；固定 0.02 s 采样步长，浏览器和服务端共用模型代码。该交付不代表已具备三维接触、摩擦、柔体或流体模型。
