# 部署设计 · v1.0

本机需要 Node.js 24，双击启动实验室.cmd 或 npm start；浏览器访问 http://127.0.0.1:4173，首次自行创建管理员。无默认账号、无 npm 安装依赖。复制 .env.example 为 .env 可配置端口、数据目录、备份周期和可选解释网关。

Docker：docker compose up --build -d，绑定回环 4173，./data:/app/data，自动备份周期 24 小时。当前环境未运行 Docker，不能把配置文件视为构建成功证明。

## 一致性备份与离线恢复

管理员页面“创建一致性备份”通过 SQLite VACUUM INTO 保存，包含关键帧 BLOB；运行时不直接复制主数据库。列表可下载到独立磁盘。BACKUP_INTERVAL_HOURS ≥1 时按周期保存，应用离线期间不调度，不删除旧快照；磁盘容量和异地保留需运维管理。

恢复步骤：停止此实例 → 检查备份路径 → 运行以下命令 → 重启 → 登录、查看任务/历史实例与关键帧。

    node tools/restore.mjs "备份完整路径.sqlite" "data" --server-stopped

工具先验证数据库完整性和必需表，再备份当前数据库为 before-restore-*，替换目标并撤销全部登录会话。必须确实停止应用，参数不是自动停服保证。恢复工具不会删学生记录，旧库可恢复；本轮在隔离测试目录演练成功。

自动快照不替代独立磁盘备份。RPO/RTO、500 人并发与可用性没有实测保证。接口 50 并行目录请求只验证轻量请求正确性，不等同课堂容量压测。

公网部署需 TLS、Secure cookie、访问控制和独立备份。SQLite 单点，node:sqlite 当前运行时仍有实验性警告；升级 Node 前跑完整测试。
